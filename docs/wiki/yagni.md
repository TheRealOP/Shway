# YAGNI and agent workflow

YAGNI means “You Aren't Gonna Need It.” Build the smallest complete behavior required by the current
task and its acceptance criteria. It is not permission to skip correctness, undo, validation,
required tests, or the creator's precise controls.

## Apply it on every task

1. Name the current user behavior and the gate it serves.
2. Read the linked contract, relevant source, and Linear acceptance criteria.
3. Reuse the editor's existing command and project model.
4. Implement one working vertical slice with inspectable results.
5. Verify realistic failure paths, record evidence, and update the affected wiki node.
6. Defer abstractions until a real second use makes their value clear.

Avoid speculative plugin systems, interchangeable backends, generic learning platforms,
new timeline models, unnecessary infrastructure, and work for imagined future requirements.
The adapter exists because there is a concrete integration boundary; it does not justify a platform.

## Keep the wiki useful

Pages are linked Markdown files with a Mermaid map. No database, generator, or knowledge-graph
framework is required. Add a page only for a distinct concept that helps implementation.
Maintain related-page links and the index map when adding/removing nodes.
Use “planned,” “verified,” and “blocked” accurately, with evidence for verified capabilities.
